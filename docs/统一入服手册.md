# 统一入服手册 —— 让 Yuki 以完整形态加入任意一台 MC 服务器

一条命令把三层进程接到目标服务器上；可选再给她一台"眼睛"（虚拟屏里的观战客户端）用于截图/视觉。

```bash
# 只有身体与大脑（聊天、派活、反射、记忆、注意力唤醒、经历胶囊）
bash scripts/world-join.sh play.example.com:25565 myserver

# 完整形态：再加虚拟屏客户端 + 相机跟随 + 截图/视觉
bash scripts/world-join.sh play.example.com:25565 myserver --camera

# 停（planner / sidecar / camera / 虚拟屏客户端 一起停）
bash scripts/world-down.sh
```

`bash scripts/world-join.sh` 不带参数会打印用法。

---

## 1. 对端服务器必须满足

| 项 | 要求 | 不满足会怎样 |
|---|---|---|
| 版本 | **26.1（Protocol 775）** | mineflayer 直接连不上；26.2 也不支持 |
| 正版验证 | `online-mode=false`（离线服） | 正版服需要正版账号或改成 Microsoft 登录，改动大 |
| 白名单 | 放行 `Yuki-chan`（主体）与 `YukiCam`（眼睛）两个名字 | 进不去 |
| 权限 | `--camera` 时 YukiCam 要是 **OP**（权限 2） | `/gamemode spectator`、`/spectate` 都敲不动 |
| 皮肤（可选） | 对端装 SkinsRestorer 之类插件 | 别人看她是一身默认皮 |

生成 OP 的命令（服务端控制台）：

```
/op YukiCam
```

## 2. 脚本做了什么

1. 把 `configs/local.json` 复制成 `/tmp/yuki-world/local.json`，覆盖 `mc.host / mc.port / mc.world`；
   `--camera` 时才打开 `snapshot.enabled` 与 `attention.snapshot_enabled`（没人抓帧时开截图只会一直失败）。
2. 起 sidecar `:8790`（mineflayer 进服）→ 起 planner `:8791`。
3. `--camera` 时再：`Xvfb :98` + `26.1.2-Fabric` 客户端（`YukiCam`，软件渲染）→ 按 F1 隐 HUD →
   `mc-camera-follow.js --mode=spectate` 让她旁观 Yuki。

记忆分区取第二个参数（`myserver`），落在 `planner/state/worlds/myserver/`。**同一台服每次用同一个分区名**，
否则记忆会分裂成几份。

## 3. 相机跟随的两种模式

| 模式 | 用在 | 机制 | 依赖 |
|---|---|---|---|
| `--mode=tp` | 自建服（`world-up.sh` / `p4-0-run.sh`） | 服务端控制台管道每 200ms 一条 `/tp`，相机精确到她的眼睛，前移 0.6 格避开头模型 | 能拿到服务端控制台 FIFO |
| `--mode=spectate` | 别人的服 | 在虚拟屏客户端里用 XTest 敲一次 `/spectate <她>`；原版旁观者跟随会一直跟着她的相机 | YukiCam 有 OP；虚拟屏在 `:98` |

`world-join.sh --camera` 用的是 `spectate`：它不需要控制台，也不会把聊天框一直打开。
重连、换目标、她死亡重生（`deaths` 变化）时会自动重敲；日志里出现 `不是旁观者`、`No player was found` 之类也会重敲。

自建服那套 `--mode=tp` 保持原样，P4.0 的真机验收就是它。

## 4. 为什么不是别的方法

- **同一个账号给客户端和 mineflayer 用**：不行。一个账号同时只允许一个连接，后连的会把先连的踢掉。
  要"客户端有画面 + 程序控制同一个人"，只能自己拿 `minecraft-protocol` 写代理（下发/上行都要改），
  26.1 的 configuration 阶段与 registry 还得按 775 的包号处理，是周级工程。
- **prismarine-viewer**：`viewer/lib/version.js` 里 `supportedVersions` 写死到 `1.21.4`，26.1 会在
  `setVersion()` 直接返回 false；它的 `lib/headless.js` 确实能出第一人称帧，但还额外依赖未安装的
  `node-canvas-webgl`，且要把 26.1 的方块/纹理图集补上。
- **SpectatorPlus 一类插件**：它加的是旁观菜单、跟随菜单、传送，不解决"谁去敲 /spectate"。
  原版 `/spectate` 本身就会跟着目标的相机，不需要额外插件（而且对端未必是 Bukkit）。
- **服务端模组**：服务端没有渲染管线，出不了第一人称画面。

## 5. 排错

| 现象 | 看哪里 |
|---|---|
| bot 没进服 | `/tmp/yuki-world/sidecar.log`（版本不符、白名单、正版验证都会在这里报） |
| planner 没起来 | `/tmp/yuki-world/planner.log` |
| 客户端没连上 | `/tmp/mc-client/client.log`（`Connecting to` 之后若出现 `Connection lost` 就是被踢/连不上） |
| 相机不跟 | `/tmp/yuki-world/camera.log`；确认 YukiCam 真的拿到了 OP（`ops.json`），并且客户端已经进服 |
| 截图全黑/一片糊 | `mc-shot.sh` 能出图但 `sanity` 会判废：相机陷进方块了，等她自己走开再拍 |

## 6. 「看一眼」：look 工具与 snapshot 技能

她不是只有文字感知。两条路共用同一个后端（`planner/look.py` → `snapshot.capture()` → `ffmpeg x11grab` 抓 `:98`）：

| 谁来要 | 怎么走 | 结果 |
|---|---|---|
| L1 自己（`look` 工具，参数只要一句 reason） | L1 → 抓帧 → **原图进 L1 的上下文** → 她自己描述 | 一次视觉调用（图约 1–1.5k prompt token） |
| L2 规划（`snapshot` 技能，可带 yaw/pitch 或 x/y/z） | L1 →`intention`→ L2 → L3 转头 → 收尾时 planner 抓帧 → 原图回 L1 | 同上 + 两次规划 |

- **不设频率上限**（机主定：由她自己决定）。拍不到就如实说"看不见"，不编画面。
- 画面可用性检查仍在：黑屏（亮度 < 25）或单一大色块（占比 > 55%）直接判废，不送模型。
- 另外，**注意力自动截图**（P5）现在也把原图交给 L1，视觉摘要仍写进胶囊与记忆。
- 前提：`world-up.sh` / `world-join.sh` 必须带相机（`--camera` 或 `p4-0` 那套），否则 `:98` 上没有画面，她只会看到"眼睛看不见"。
