# 项目公约 · Yuki × Minecraft

> 本文件是长期协作的规则，不是产品设计。产品设计看 `PRD.md`，进度看 `HANDOFF.md`。
> 违反公约的实现即使"能跑"也算不合格。

---

## 一、这个项目是什么

让已有的人格 Agent「Yuki」（Python，跑在机主电脑上的个人助手 / 电子妹妹，QQ 场景已稳定）真的住进 Minecraft：听得懂自然语言、能自己动手、有自己的喜好，而不是一个执行任务的机器人。

**成功的样子**：机主在公屏说"去挖点石头"，她用自己的人设语气应一声，去挖，挖完回来说"挖好啦"；机主不理她的时候，她会自己跑去看看那片南瓜。

**明确不是**：不是 MC AI benchmark，不是刷通关速度，不是通用 Agent 框架。

---

## 二、工作原则

1. **只做被要求的事**。不顺手重构、不补充"更好的做法"、不扩大范围。任务完成即停。
2. **需求不清楚就问**，不揣测后开工。涉及取舍、风险，先说清楚再动。
3. **遇到需要机主介入的步骤立即停下**（sudo、手动安装、交互式登录、需要人肉眼判断的效果），说明卡在哪、需要做什么，然后等。
4. **一次只推进一个可验收的小步**。每个 session 结束必须留下：改了什么、当前状态、下一步。
5. **不确定就实测**。所有"应该可以""通常支持"的结论，必须用一次真实调用验证过才能写进文档。
6. **先修链路，再修体验**。链路不通的时候不调 prompt。

---

## 三、技术红线（不得违反）

| 红线 | 原因 |
|---|---|
| 不开发 Fabric Mod、不反编译、不写 Java | 机主内存不足，且已有更轻的替代（原版 spectator + 系统截屏） |
| 版本钉死 26.1（协议 775） | mineflayer 上限；26.2 = 776 不支持 |
| 不做本地小模型 | 无 GPU，内存 7GB 且占用高 |
| 保命逻辑（priority 9）不得交给模型决定 | 死亡/岩浆/濒死不能等 LLM |
| MC 原始事件流、坐标表、完整背包表不得进入 L1 上下文 | 会淹没人格，且成本失控 |
| 任何模型的输出必须先过 schema 校验才能进执行器 | 脏 JSON 会直接卡死状态机 |
| 不在主服 `server/` 上做未备份的破坏性操作 | 那是机主的存档 |
| 不把 API key、密码写进文档或提交 | `configs/config.yaml` 已在 .gitignore |

## 四、文档纪律

| 文件 | 职责 | 更新时机 |
|---|---|---|
| `PRD.md` | 产品定义、接口契约、阶段验收 | 需求变化时 |
| `HANDOFF.md` | 进度、下一步、命令、坑、冻结决策、给新 session 的简报 | **每个 session 收工必改** |
| `memo/Log.md` | 流水账，append-only，只加不改 | 每个 session 追加一条 |
| `docs/项目公约.md` | 本文件，协作规则 | 规则变化时 |
| `LLM接入MC方案.md` | 早期讨论，历史参考 | 不再维护 |

**约定**
- 文档里写的命令必须能直接复制执行（路径全写、变量不留空）。
- 结论要带依据：实测过就写"实测"，没实测就标"未验证"。
- 决策一旦冻结（见 `HANDOFF.md` 第 4 节），新 session 不得重新论证；要推翻必须先改那一节并记录理由。

## 五、代码纪律

1. **技能统一签名**：`async (args, ctx) => { ok, detail }`，不许有例外，否则状态机无法统一处理。
2. **一切外部输入当不可信**：模型输出、玩家聊天、服务端数据，都要校验/兜底。
3. **所有 LLM 调用必须有超时与降级**；任何一层挂掉，bot 不能卡在原地，超时即回空闲态。
4. **失败要能被观察到**：状态机每一步都打结构化日志（步骤名、参数、结果、耗时）。
5. **不静默失败**：`bot.chat('/cmd')` 这类无返回的调用，必须用世界状态二次确认（本项目已踩过：没 op 时命令静默无效）。
6. **配置外置**：主机、端口、用户名、模型名走环境变量或配置文件，不硬编码。
7. **不写"以防万一"的抽象**。三个技能时不要写插件注册框架。

---

## 六、验收纪律

- 每个阶段的验收条目是**硬门槛**，达不到不得进入下一阶段；可以缩小范围（明确写进 PRD），但不能口头放行。
- 每次改动技能库/状态机后，必须跑 `yuki-bot/scripts/compat-test.js` 确认没有回归。
- "体验类"验收（像不像活着、语气对不对）只有机主能判，模型自评无效。
- 涉及钱的指标（token、API 调用次数）必须记账，超预算即降级。

---

## 七、Session 协作协议

**开工（三分钟）**
1. 读 `HANDOFF.md` 第 0–4 节
2. 读 `memo/Log.md` 最后 30 行
3. 检查常驻进程：`ss -lntp | grep -E '25565|25566'`

**收工（必须做完）**
1. 更新 `HANDOFF.md` 第 2 节（状态）、第 3 节（下一步/勾选）
2. `memo/Log.md` 追加一条
3. 新坑补 `HANDOFF.md` 第 5 节；新决策补第 4 节
4. 涉及 Yuki 本体的改动，在 `/home/asumi/Yuki` 的 git 仓库提交

**禁止**
- 不写交接就结束 session（下一个 session 会从错误的前提出发）
- 同一个决定在两个 session 里得出相反结论而不留记录

---

## 八、长期节奏

这是一个长周期项目，预期跨几十个 session 迭代。原则：**每一步都要能独立演示**。宁可慢，也不要出现"一周后才发现整条链路方向错了"。
